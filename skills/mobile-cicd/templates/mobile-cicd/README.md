## Releasing

```bash
git checkout main && git pull
git tag -a v1.2.3 -m "What's new in this version"
git push origin v1.2.3
gh run watch
```

- The version (`1.2.3`) comes from the tag. The build number is the highest one App Store Connect
  or Google Play has seen, plus one, so it never collides and nothing is committed back.
- The tag message is the App Store "What's New" text (a tag without `-a` gets
  "@@release.defaultNotes@@").
- iOS: the build is uploaded, then a Linux job waits for Apple's processing and submits it for
  review. Android: the bundle goes to the production track.

What "production" means is set at the top of `mobile-release.yml`:

| Setting | Now | Meaning |
| --- | --- | --- |
| `IOS_SUBMIT_FOR_REVIEW` | `@@release.iosSubmitForReviewText@@` | `false`: upload only, submit by hand in App Store Connect |
| `IOS_AUTOMATIC_RELEASE` | `@@release.iosAutomaticReleaseText@@` | `false`: after approval, press "Release" yourself |
| `ANDROID_ROLLOUT` | `@@release.androidRolloutText@@` | below 1.0: staged rollout, raised by hand in Play Console |

## Secrets

Set them with `bash .github/mobile-cicd/setup-secrets.sh` in your own terminal. Values go from
files and hidden prompts straight to GitHub; each one is checked first. See what is set with
`bash .github/mobile-cicd/setup-secrets.sh --check`.

| Secret | What |
| --- | --- |
| `APP_STORE_CONNECT_API_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_API_KEY` | App Store Connect API key (`.p8`, base64), App Manager role |

## Before the first release

1. App Store Connect: the app record exists for `@@ios.bundleId@@`. For the very first version,
   fill in the listing (screenshots, description, privacy, age rating) or the submission is
   refused. The build itself uploads fine.
2. Google Play: the app exists for `@@android.packageName@@`, and its **first `.aab` was uploaded
   by hand** (the API cannot create an app). The service account is invited in Users and
   permissions with release rights.
3. Google Play, personal developer accounts created after November 2023: production needs a
   closed test with at least 12 testers for 14 days first. Until then, production uploads fail.
4. Until the app's first Play release is published, uploads arrive as drafts: publish that first
   one in Play Console.

## When something fails

| Symptom | Fix |
| --- | --- |
| Gate: "not on main" | Tag a commit that is in `main` (merge first), delete and push the tag again |
| Next build number: Google Play did not answer | Service account access, or the first `.aab` was never uploaded by hand |
| iOS signing errors | `setup-secrets.sh ios`: certificate expired, or the profile does not include it |
| "Missing Compliance" / export compliance | Add `ITSAppUsesNonExemptEncryption` to Info.plist (Expo: `ios.config.usesNonExemptEncryption`) |
| Android: "not signed with the upload key" | `ANDROID_KEYSTORE` holds a different key than Play expects; compare SHA-256 in Play Console -> App integrity |
| Play: "draft app" | Publish the first release in Play Console once; later ones go out by themselves |

Re-run a failed release from the Actions tab (Re-run failed jobs). A build number that was
already uploaded is skipped automatically on the next tag.
